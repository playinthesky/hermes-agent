1. 발명의 배경 및 목적

1.1 배경 기술의 한계

기존 오프라인 숙의 토론회·대규모 모임의 한계:

1. 편향된 소그룹 구성 — 임의/신청순 배정 시 특정 테이블에 동질 성향(성별·연령·입장)이 몰려 다양한 의견 교환이 차단됨.

2. 실시간 분석 불가 — 발언을 수기 기록하거나 종료 후 녹취 전사하여 사후 분석 → 진행 중 흐름 파악·동적 운영 불가.

3. 분석 데이터 구조화 부재 — 녹취록은 텍스트 나열에 불과해 '관점·입장·맥락'의 다차원 분류·통계화 곤란.

4. 비조건화 분석 — 분석 시 토론 쟁점을 명시 기준으로 삼지 않으면 입장(찬/반)을 쟁점에 상대적으로 정확히 판정하기 어려움.

1.2 해결 과제

  • 인구통계·의견 다양성 극대화 (2축·2단계 자동 배정)
  • 진행 흐름을 막지 않는 실시간 비동기 발언 구조화 분석
  • 쟁점에 조건화된 일관된 입장 판정
  • 실시간 교차집계 + 동적 토픽 모델링
  • 입론 결과 기반 상호토론 진행자료 생성(지향)

2. 발명의 핵심 요약 및 신규성

2.1 전제 (변리사 최우선 확인)

새로운 AI 모델 개발이 아니라, 사전학습 대규모 언어모델(LLM) 과 음성인식(ASR) 을 토론 진행 맥락에서 조건화·연쇄·배치한 시스템/방법. 신규성은 *모델*이 아니라 *운용 구조*에 있음.

2.2 도입 AI 기능 4종 (기호)

기호기능(기술명)입력 → 출력적용
Ⓐ음성인식(ASR/STT)음성→텍스트발언 입력
Ⓑ대상 조건화 입장·논증 추출 (target-conditioned stance detection + argument mining)(쟁점+발언)→관점·입장·맥락·요약(JSON)입론 분석(핵심)
Ⓒ의미 군집·토픽 + 추상요약발언집합→토픽 3~5개실시간 집계
Ⓓ제어된 자연어 생성입론분석→상호토론 쟁점·질문진행지원(지향)
∅(AI 아님) 규칙·알고리즘—배정·수치집계

2.3 신규성 5요소 (운용 구조)

1. 쟁점 조건화 — 입장을 쟁점에 상대적으로 판정

2. 입력 비차단 비동기 파이프라인

3. 미시(개별 발언) → 거시(집계·군집) 2층 분석

4. 분석 → 생성 연쇄 (이해를 넘어 진행자료 생성)

5. 사람(퍼실리테이터) 검수 루프 (human-in-the-loop)

3. 운영 흐름

[회원·인증] → ① 랜덤 배정 → ② 입론 → ③ 상호토론 → (실시간 분석·집계)
  • ① 랜덤 배정 — NGT 기반, 2축(인구통계 × 의제 태도) 다양성을 테이블 간 균형 배정
  • ② 입론 — 제시된 쟁점에 대한 참여자의 [입장 + 근거] 진술(음성→텍스트). 단순 전사가 아님. (인식조사=사전/현장 투표는 별개 단계)
  • ③ 상호토론 — 입론 기반 쟁점 정리(Ⓓ, 지향) + 발언 기록
  • 집계 — 쟁점별·속성별 분포 + 토픽 군집

랜덤 배정 2축 (기본/심화)

  • 인구통계 축 — 기본: 성별·연령대·지역 / 심화: 추가속성(직업·학력 등, 해외는 인종·국적 등)
  • 의제 태도 축 — 기본: 긍정·부정·유보 / 심화: 세분 척도

4. 제1 기술영역: 다차원 가중치 기반 참가자 층화 배정

2단계 하이브리드 최적화 알고리즘.

흐름: 참가자·테이블 입력 → [Phase1 씨앗배정: 테이블마다 다양성 점수 최대 조합 선정] → [Phase2 균형배분: 남은 인원을 속성중복 패널티 최소 테이블에 배정] → 배정결과·불균형 통계 출력.

4.1 1단계: 씨앗 배정 (Seed Assignment)

  • 테이블 수용력에 따라 씨앗 크기 결정 (수용력 ≥7 → seed_size=3, <7 → 2)
  • 풀 앞부분(예: 40명)에서 seed_size 조합 생성(연산 타임아웃 방지)
  • 다양성 점수 = UniqueCount(성별) + UniqueCount(연령대) + UniqueCount(입장)
  • 3명 조합이 모두 다르면 최대 9점(3+3+3)
  • 최고 점수 조합을 테이블에 배정·풀에서 제거 (테이블 수만큼 반복)

4.2 2단계: 균형 배분 (Balanced Distribution)

  • 남은 풀 무작위 셔플 (순서 편향 제거)
  • 각 참가자 p에 대해 테이블 T별 배정점수:
  • Score(T,p) = −(pos_dup×4 + gen_dup×2 + age_dup×2) − |T|×0.1
  • pos_dup/gen_dup/age_dup = T 내 입장/성별/연령 동일 인원 수, |T| = 현재 인원
  • 가중치: 입장 4(의견 다양성 우선), 성별 2, 연령 2, 인원수 0.1
  • 수용 한도 미초과 테이블 중 점수 최대 테이블에 배정

4.3 수도코드

def run_stratified_assignment(participants, num_tables, table_capacity):
    seed_size = 3 if table_capacity >= 7 else 2
    pool = list(participants)
    assignments = {i + 1: [] for i in range(num_tables)}

    def diversity_score(sel):
        return (len(set(m.get('성별') for m in sel))
              + len(set(m.get('연령대') for m in sel))
              + len(set(m.get('입장') for m in sel)))

    # Phase 1: 씨앗 배정
    for t in range(1, num_tables + 1):
        if not pool: break
        if len(pool) < seed_size:
            assignments[t].extend(pool); pool = []; break
        search_pool = pool[:min(len(pool), 40)]
        best_combo, best = None, -1
        for combo in combinations(range(len(search_pool)), seed_size):
            sel = [search_pool[i] for i in combo]
            s = diversity_score(sel)
            if s > best:
                best, best_combo = s, combo
                if s == seed_size * 3: break   # 완벽 다양성 조기 종료
        if best_combo:
            chosen = [search_pool[i] for i in best_combo]
            assignments[t].extend(chosen)
            pool = [p for p in pool if p not in chosen]

    # Phase 2: 가중치 균형 배분
    random.shuffle(pool)
    for p in pool:
        best_table, best = None, -float('inf')
        for t in range(1, num_tables + 1):
            if len(assignments[t]) >= table_capacity: continue
            m = assignments[t]
            pos = sum(1 for x in m if x.get('입장')   == p.get('입장'))
            gen = sum(1 for x in m if x.get('성별')   == p.get('성별'))
            age = sum(1 for x in m if x.get('연령대') == p.get('연령대'))
            score = -(pos*4 + gen*2 + age*2) - len(m)*0.1
            if score > best: best, best_table = score, t
        if best_table: assignments[best_table].append(p)
    return assignments

5. 제2 기술영역: 비동기 LLM 발언 구조화 분석 (쟁점 조건화) — *핵심*

발언 입력 → DB 임시행(분석중⏳) 생성 → 즉시 응답 → 백그라운드 스레드가 LLM 분석 → 결과로 행 갱신 → 집계 트리거.

흐름(시퀀스):

1. 클라이언트 → 서버: POST /api/analyze (발언, 쟁점, 테이블, 참가자)

2. 서버 → DB: 로우 추가 ("분석 중 ⏳")

3. 서버 → 클라이언트: 즉시 응답(비차단)

4. (백그라운드) 서버 → LLM: 쟁점 컨텍스트 + 발언 원문

5. LLM → 서버: 구조화 JSON (관점·입장·맥락·요약)

6. 서버 → DB: 해당 로우 E~H열 갱신 → 대시보드 통계 트리거

5.1 작동 메커니즘

1. 동기 기록 — 상태 "분석 중 ⏳"으로 행 즉시 추가

2. 비동기 분기 — 메인 스레드는 즉시 응답, threading.Thread로 분석 분기(응답 차단 방지)

3. 쟁점 조건화 프롬프트 — LLM에 현재 쟁점(Agenda) + 발언 원문 주입, 4차원 구조 출력 강제:

  • 관점(Perspective): 문제를 보는 시각의 축 (예: 경제적 실효성, 사회적 형평성)
  • 입장(Position): 해당 쟁점에 대한 찬/반/중립 — *쟁점에 상대적으로 판정*
  • 맥락(Context): 관점·입장을 지지하는 근거·논리적 배경
  • 요약(Summary): 한 줄 요약

4. 파싱·갱신 — 구조화 JSON 파싱 후 시트 Row ID 매핑하여 칼럼 실시간 갱신

신규성 포인트(§2.3-①): 일반 요약과 달리 "이 쟁점에 대해"를 명시 기준으로 넣어 입장을 쟁점 상대적으로 판정 → 쟁점별 정량 집계의 기반.

6. 제3 기술영역: 실시간 교차집계 + 동적 토픽 클러스터링

흐름: 발언 DB → (참가자 인구통계 조인) → 교차집계(성별×입장, 연령×입장, 지역×입장) / 최근 N개 발언 → LLM 토픽 군집(3~5개) → 통계탭 갱신·대시보드 표출.

6.1 실시간 교차 집계

  • 발언 결과의 참가자 ID로 참가자 시트(인구통계)를 조인
  • 성별×입장 / 연령대×입장 / 지역×입장 분포 집계 → 통계 리포트 구성

6.2 LLM 동적 토픽 클러스터링

  • 데이터 윈도윙 — 최근 N개(예: 50개) 발언 슬라이딩 윈도우 추출
  • 논점 군집화 — LLM이 관통 토픽 3~5개를 군집·마크다운 요약
  • 자동 동기화 — 교차집계 + 토픽 요약을 통계탭에 실시간 기록 → 운영진·분석팀 실시간 파악

7. 제4 기술영역(지향): 입론 기반 상호토론 쟁점 생성 (Ⓓ)

입론(§5) 분석과 집계(§6)를 종합·재구성하여, 퍼실리테이터가 상호토론을 진행하는 데 필요한 쟁점·질문을 생성해 제시. 추출·요약(이해)을 넘어 생성(generation) 으로 전환되는 지점. *(현재 미구현, 필수 보강 항목)*

8. 특허 청구항 초안

구편수 초안(청구항 1~4) + 신규성 보강 청구항(5~7). HWPX(구 청구항4)는 부록 A·별도 출원으로 이관.

[청구항 1] (독립) 다차원 속성 최적화 기반 토론 참가자 소그룹 배정 시스템

참가자의 인구통계학적 정보 및 사전 토론 입장을 포함하는 복수 속성을 수집하는 데이터 입력부; 복수 소그룹 테이블에 참가자를 배정하는 알고리즘 연산부;를 포함하되, 상기 연산부는 (가) 소그룹별 씨앗 크기에 대응하는 조합을 탐색 서브풀에서 생성하고 조합 내 속성 고유값 개수 기반 다양성 점수를 산출하여 최대 조합을 우선 배정하는 1단계 씨앗 배정 모듈; (나) 잔여 참가자를 셔플 후 각 참가자별로 기존 멤버와의 속성 중복 패널티를 차감한 배정 점수를 계산하여 최대 테이블에 순차 배분하는 2단계 균형 배분 모듈;을 포함하는 것을 특징으로 하는 시스템.

[청구항 2] (종속) 청구항 1에서, 배정 점수는 입장 중복도·성별 중복도·연령 중복도 및 테이블 현재 인원수에 서로 다른 패널티 가중치(입장 > 성별=연령 > 인원수)를 곱해 음의 값으로 합산하여 산출하는 것을 특징으로 하는 시스템.

[청구항 3] (독립) 비동기 LLM 분석 파이프라인 및 실시간 대시보드 숙의 토론 지원 방법

웹 서버가 발언 데이터와 토론 쟁점 정보를 포함하는 분석 요청을 수신하는 단계; DB에 신규 로우 생성·진행상태 기록(동기 저장) 단계; 클라이언트에 즉시 응답 후 백그라운드 비동기 스레드를 분기하는 단계; 상기 스레드가 LLM에 쟁점 정보 및 발언을 주입하여 관점·입장·맥락·요약을 추출(구조화)하는 단계; 결과를 해당 로우에 칼럼별 갱신하고 전체 DB 기반 통계·동적 토픽 군집을 재집계하여 대시보드 탭에 갱신하는 단계;를 포함하는 방법.

[청구항 4] (종속) 청구항 3에서, 상기 입장은 상기 토론 쟁점을 분석 기준 컨텍스트로 명시하여 해당 쟁점에 상대적으로 판정되는 것을 특징으로 하는 방법. *(신규성 핵심)*

[청구항 5] (종속) 청구항 3에서, 상기 비동기 스레드 분기 시 상기 로우의 분석 항목 영역에 분석 진행중 자리표시자를 기록하고 분석 완료 시 해당 영역을 갱신하여, 발언 입력 흐름이 분석 완료를 대기하지 않는 것을 특징으로 하는 방법.

[청구항 6] (종속) 청구항 3에서, 상기 추출된 분석 결과 및 집계 결과를 종합하여 후속 상호토론을 위한 쟁점 또는 질문을 생성하여 진행자 단말에 제공하는 단계를 더 포함하는 방법. *(Ⓓ)*

[청구항 7] (종속) 청구항 3에서, 상기 발언은 음성인식으로 전사된 텍스트이며, 상기 입장 판정은 발언 언어와 무관하게 상기 쟁점을 기준으로 수행되는 것을 특징으로 하는 방법. *(해외·교차언어)*

부록 A. HWPX 공문서 서식 자동 검증 기술 (별도 출원 후보)

한국 공문서(HWPX) 내부 XML을 파싱해 서식 표준(폰트·크기·자간·행간·여백)을 자동 검증·등급 산출. 본 토론시스템과 별개 발명 — 독립 출원 권장.

메커니즘

1. 컨테이너 해제 — HWPX(OWPML, ZIP)에서 Contents/header.xml(글자모양 메타)·Contents/section0.xml(문장 서식) 로드 → XML 트리

2. 표준 검증 (한국 공문서 표준과 대조)

  • 본문/제목 폰트: header.xml fontface → 표준(본문 함초롱바탕 등) 대조
  • 글자크기·자간: section0.xml charPr의 height(1/100pt)·letterSpacing → 본문 11pt, 자간 −3%
  • 행간·정렬: paraPr의 lineSpacing·정렬 → 160~180%, 양쪽정렬
  • 용지 여백: pagePr margin → HWPUNIT(1mm=283) → mm 환산, 기준 비교

3. 등급 산출 — Ratio = Pass÷전체

  • ≥0.95 → 5등급 / 0.80~0.95 → 4 / 0.60~0.80 → 3 / 0.40~0.60 → 2 / <0.40 또는 치명 Fail → 1등급

[별도 청구항] OWPML XML 파싱 기반 HWPX 서식 표준 검증 시스템 — 파일 해제부 / 서식 파싱부 / 표준 검증부 / 등급 연산부를 포함.
