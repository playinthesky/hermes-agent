## 1. 의뢰 개요

- **한 줄 요약**: 고객지원팀이 사내 문서(정책·FAQ·매뉴얼) 검색 챗봇을 도입해 1차 응대 부담을 줄이려 함.
- **배경·문제**: 문서가 Notion/PDF에 흩어져 있어 상담원이 답을 찾는 데 시간이 걸림.
- **성공 기준**: 상위 20개 FAQ에 대해 정답 문서를 근거와 함께 80%+ 정확도로 반환.

## 2. 범위

- **포함**: 문서 인덱싱, 벡터 검색, 근거 인용이 붙은 대화 응답, MCP 도구화.
- **제외**: 외부 고객 직접 노출(이번엔 내부 상담원용), 멀티링구얼.
- **가정·제약**: 온프레미스 선호(데이터 외부 반출 제한), 4주, GPU 1대.

## 3. 솔루션 설계 (역량 매핑)

| 단계 | 활용 스킬 | 활성/설치 | 산출물 |
|------|-----------|:---------:|--------|
| 문서 수집·정규화 | `ocr-and-documents`, `notion` | ✅ | 정규화된 문서 코퍼스 |
| 임베딩·벡터 저장 | `chroma` (온프레미스) ‹대체: `qdrant-vector-search`› | ⬇️ | 벡터 인덱스 |
| 검색 도구화 | `fastmcp` | ⬇️ | 검색 MCP 서버 |
| 대화 오케스트레이션 | `hermes-agent` | ✅ | 근거 인용 챗봇 |
| 품질 평가 | `evaluating-llms-harness` | ⬇️ | 정확도 리포트 |

> 온프레미스 제약 때문에 벡터DB는 클라우드형 `pinecone` 대신 자체 호스팅 `chroma`/`qdrant` 선택.

## 4. 산출물

- RAG 파이프라인(인덱싱 + 검색)
- 검색 MCP 서버 + 챗봇 인터페이스
- 정확도 평가 리포트, 운영 가이드

## 5. 일정·마일스톤

| 마일스톤 | 내용 | 일정 |
|----------|------|------|
| M1 | 코퍼스 정규화 + 인덱싱 | 1주차 |
| M2 | 검색·챗봇 통합 데모 | 3주차 |
| M3 | 평가·튜닝·인수 | 4주차 |

## 6. 준비물·의존성

- **자격증명**: Notion API 토큰, (사용 시) LLM 추론 엔드포인트.
- **데이터**: 사내 문서 export 권한.
- **환경**: GPU 1대, 온프레미스 벡터DB 호스팅.

## 7. 리스크 & 대응

| 리스크 | 영향 | 대응 |
|--------|------|------|
| 문서 품질 편차 | 중 | `ocr-and-documents` 전처리 강화, 청크 전략 조정 |
| 환각(근거 없는 답) | 상 | 인용 강제 + `evaluating-llms-harness`로 회귀 측정 |

## 8. 적립 메모

- **재사용 포인트**: 온프레미스 RAG 스택(`chroma`+`fastmcp`+`hermes-agent`) 구성은 사내검색 의뢰에 그대로 재사용.
- **회고**: 청크 크기·인용 포맷이 정확도에 가장 큰 영향.
