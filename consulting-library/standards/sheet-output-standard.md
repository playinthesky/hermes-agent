# 시트·산출물 형식 표준 v0.1

> 코리아스픽스 산출물(스프레드시트·문서)을 생성하는 모든 에이전트가 따르는 형식 규칙.
> 근거: 기존 실물 문서(견적서 표준, 워크숍 커리큘럼 시트)의 형식 언어 + 대표님 교정 지시.
> **대표님의 새 교정 지시가 구두로 나오면, 그 턴 안에 이 문서에 추가한다. 예외 없음.**

## 제0조 — 복제 우선 원칙

**형식을 발명하지 않는다. Drive에서 같은 용도의 최신 실물 시트를 찾아 복제(copy)한 뒤
내용만 교체한다.** 코리아스픽스의 운영 시트(입론 및 상호토론, 견적서 표준 등)는 행사마다
복제되며 진화해 온 검증된 도구다. 실물 검색 1~2회로 못 찾았다고 새로 만들지 말고,
사람에게 실물 위치를 묻는 것이 새 형식을 발명하는 것보다 낫다.
(2026-07-03 부동산 건 — 실물 「입론 및 상호토론(SH)」이 있는데 CSV로 재발명한 실수에서)

## 스프레드시트 공통 규칙

1. **첫 행은 헤더, 반드시 틀고정(setFrozenRows(1))한다.** 출력·집계·기록 시트 전부.
   (2026-07-03 대표님 지시 — "매번 놓친다"는 지적과 함께. 다시 놓치면 안 됨)
2. 헤더는 한국어, 사람이 읽는 말로 쓴다. 코드가 필요하면 "옵션 (코드)" 형태로 병기.
3. 표 상단에 메타 블록을 둔다: 의뢰기관 / 프로젝트 분류 / 의제 / 규모 / 장소 / 일자 / 담당자
   (견적서 표준의 General Condition 블록과 동일한 관행).
4. 행 계층은 「구분 → 항목 → 세부내용 → (수치 열) → 비고」 순서를 따른다.
5. **사람이 열어서 10초 안에 구조를 이해하고 손으로 고칠 수 있어야 한다.**
   설명이 필요한 수식 덩어리·CONFIG 수정이 전제된 스크립트는 산출물이 아니라 부채다.
6. 수식은 합계·건수 등 자명한 것만. 복잡한 집계가 필요하면 별도 열에 풀어서 단계별로.
7. 자동화(Apps Script 등)는 문서 뒤에 숨는다. 자동화가 죽어도 그 시트만으로 사람이
   일을 계속할 수 있어야 한다 (종이 백업 원칙).
8. 인쇄를 전제한다: A4 가로/세로 한 장에 표가 잘리지 않게 열 수를 설계.
9. 탭 명명: 앞자리 숫자로 정렬 (00_코드북 · 01_참가자 · 20_분석 · 90_집계 · 95_화면출력).
10. 파일명: `YYMMDD_제목 vX.Y` (표준 문서 규칙과 동일).

## 화면 출력(투사)용 시트 규칙

- 첫 행 헤더 고정 + 글자 크기 20pt 이상, 옵션명은 말머리 위주로 짧게.
- 한 화면 = 한 문항. 스크롤이 필요하면 실패한 설계.
- 막대는 SPARKLINE 등 셀 안에서 완결되는 방식만 (외부 차트 배치는 수동 조정 유발).
