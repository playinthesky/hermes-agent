# 숙의토론 문항 설계·검토

공론장(원탁토론·공론조사·워크숍)의 토론 문항과 택1 옵션을 설계하거나 검토할 때 사용한다.
근거: 코리아스픽스 퍼실리테이터 2급 워크북(의제화 3기준), OECD 숙의 모범원칙,
`consulting-library/FRAMEWORK.md`의 의제화 판단 절차.

## When to Use
- 진단/시나리오 토론의 문항·옵션 초안 검토 요청
- 새 공론 의제의 택1 문항 설계
- 기존 문항의 편향·커버리지 점검

## 절차 (순서 고정)

1. **문항 유형 판별** — 진단(현상 인식) / 시나리오(미래 가치 선택) / 감수(트레이드오프) / 우선순위(자원 배분)
2. **이해관계자 역방향 매핑** — 옵션이 아니라 이해관계자 목록에서 출발해, 각 이해관계자가
   고를 옵션이 있는지 확인. 공백·과대대표(한 집단이 옵션 2개 이상)를 표로 드러낸다.
3. **3기준 채점** — 옵션마다 시의성(최신 여론·통계 근거 필수), 대립성(누구와 갈리는지 명시),
   공적 영향력(사적 이익 프레임은 진단용만 허용). 근거 없는 등급은 무효.
4. **구조 검증** — 상위-하위집합 혼재 금지(집계 불능), 층위 혼입 금지(지역 축·세대 축 분리),
   "아무도 반대하지 않는 옵션"은 죽은 선택지로 제거/교체.
5. **편향 점검** — 사회적 바람직성(낙인 어휘 중립화: 갭투자→자산 형성), 문항-옵션 층위 불일치
   (공적 질문 + 사적 이유 조합은 특정 옵션 유도), 무난한 중도 옵션 쏠림 위험.
6. **트레이드오프·제외 기록** — 옵션 수 vs 집계 해상도 트레이드오프 명시,
   검토 후 제외한 옵션과 사유를 반드시 남긴다(검증위 제출용 공정성 증빙).

## 문항 유형별 규칙

- **진단 토론**: 인식 지형을 드러내는 게 목적 — 공적 영향력 낮아도 대립성 높으면 포함 가능.
- **시나리오 토론**: 각 옵션에 **"감수할 것"을 옵션 본문 최상단에 선행 배치**(공짜 선택 차단).
  이유 개수는 옵션 간 동일(균형 원칙).
- **감수(트레이드오프) 문항**: "감수할 수 있는 것"(동어반복)이 아니라
  **"가장 감수하기 어려운 것"(부정형)**으로 묻는다 — 마지노선이 드러난다.
  시나리오 문항과 1:1 대응시키면 D×E 정합성(자기 선택의 대가 수용 여부) 분석이 가능.
- **우선순위 문항**: 옵션은 상호 배타·동일 층위 필수. 우산 개념 금지.

## 출력 형식

- 옵션마다 **(말머리)** 2~4자 라벨 — 조별 기록·집계·코드북의 코드가 된다 (A1.., B1.., D1..).
- 확정본은 복사 시 번호가 유지되도록 일반 텍스트 블록으로 제공.
- 하위 이유 번호는 "1." 스타일, 대분류와 구분되게.

## 실행문서 연계 (설계 후 반드시 이어서)

문항 확정 → ① 코드북(시트 00탭) 반영 → ② 사전·사후 조사 문항 정렬(같은 옵션 문안, 참가자ID
매칭 키) → ③ 자료집 근거 명세(옵션별 데이터 대칭) → ④ 퍼실 브리핑 킷(§중립 수칙에 편향
유의점 반영) → ⑤ 집계·전후비교·화면출력 탭 → ⑥ 당일 플래시 리포트.
Google 스택 자동 구축은 Apps Script 워크북 빌더 패턴(탭 생성 + FormApp 폼 생성 + setDestination) 사용.

## Pitfalls
- 급하다고 표면 문구만 다듬고 2~6단계를 건너뛰면 반드시 공백이 남는다 (검증 절차 생략 금지).
- 사후 재질문 옵션 문안이 사전 조사와 한 글자라도 다르면 전후비교 COUNTIF가 깨진다.
- 사전 조사에 참가자ID가 없으면 개인 단위 의견 변화 추적이 불가능 — 설계 시점에 확보.
